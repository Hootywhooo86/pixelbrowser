# Bit Browser 0.5.6: Shippo labels open

Your download log showed the real problem. Shippo's "Download label" asks Shippo's server for the label (`label_regen`), and the answer contains the label's address. Shippo's own pop-up code then fails with "Cannot read properties of null (reading 'close')" on the phone, so the label never appears.

Bit Browser no longer depends on that pop-up code. When a page gets back an answer containing a label or PDF link right after you tap, and nothing else saves the file within a moment, Bit Browser saves it from that link and opens it in the **PDF viewer** (Print / Save / Share).

The download log now also shows **"file link in answer"** and **"saving from link"** lines, so it's clear what happened.
